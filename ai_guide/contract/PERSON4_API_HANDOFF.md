# Person 4: route API contract

Backend version: commit `be9bf1a`, branch `moiz/person1-core`.
Your AI guide can run `POST /ask` on port 8001 and call our backend `POST /route` on port 8000.
The adjacent request and response JSON files were generated by the actual planning engine. `openapi.json` supplies the exact API schema.

## Request

Send JSON with `Content-Type: application/json`. Use `route-request.json` as a working example.

- `start`: exactly `{ "row": integer, "col": integer }` OR `{ "lon": number, "lat": number }`. Never mix coordinate pairs. Longitudes accept signed or 0–360 east.
- Supply either `goal` (same position format) OR `goal_type: "ice"`. Ice is the only automatic goal type.
- `oxygen_hours`: available time in Earth hours, default 4; `battery_wh`: energy in Wh, default 1000.
- `reserve_fraction`: default 0.2; `return_to_start`: default true.
- `local_time_h`: 0, 6, 12 or 18; default 12. `mode`: `scenario` (default) or `observations`.
- `min_goal_distance_km`: if omitted and the start meets the ice threshold, a 2 km minimum is applied. Explicit 0 permits a stationary result. Our sample requests 3 km.
- `avoid`: any combination of `steep`, `dust`, `cold`, `unknown_thermal`. Steep tightens the slope ceiling to 10 degrees; dust applies the configured optical-depth ceiling (default 1); cold requires at least the cold-reference temperature (default 230 K); unknown_thermal requires historical temperature coverage. Dust avoidance is unavailable in observations mode.
- Unknown fields are rejected. Keep intent fields such as `question` in your service; do not forward them to `/route`.

## Response mapping

| Requested information | Actual field |
|---|---|
| Feasibility | `status`: `ok`, `infeasible` or `search_limit`; no boolean `feasible` |
| Outbound path | `route.outbound`: objects with `row`, `col`, `lon`, `lat` |
| Return path | `route.return_path` |
| Whole mission geometry | `route.geojson`, coordinates `[lon, lat]`, including return |
| Distance, whole mission | `metrics.distance_km` |
| Oxygen/time used | `metrics.hours`, in Earth hours |
| Oxygen remaining | `metrics.oxygen_remaining_hours` |
| Battery used / remaining | `metrics.battery_wh` / `metrics.battery_remaining_wh` |
| Maximum slope | `metrics.maximum_slope_deg` |
| Temperature range | `metrics.minimum_temperature_k` / `maximum_temperature_k` |
| Dust / radiation reference | `metrics.maximum_dust_optical_depth` / `radiation_reference_msv` |
| Budget bars along mission | `route.profile[].elapsed_hours`, `oxygen_remaining_hours`, `battery_remaining_wh` |
| Turnaround | `turn_back.turnaround` |
| Abort checkpoints | `turn_back.abort_points` |
| Terrain candidates | `turn_back.candidate_shelters`; unverified, no validated radiation protection |
| Assumptions and provenance | `data`; retain these limitations in AI explanations |

For a UI expecting `[lat, lon]`, map `route.outbound.map(p => [p.lat, p.lon])`. To include return, append `route.return_path.slice(1)` before mapping. GeoJSON uses the opposite coordinate order.

For a structured `hazards` object, call `POST /briefing-data` with the same request. `/route` itself has no `hazards` field.

## Failure handling

Check `status` before reading `route` or `metrics`. A valid but infeasible request returns HTTP 200 with `route: null` and `metrics: null`; see `route-infeasible-response.json`. Reasons include `no_feasible_route`, `no_eligible_goal`, `search_limit`. Never explain an infeasible or search-limited result as a successful trip.

HTTP 422 means invalid input, out-of-grid position, blocked start or unsupported constraint. HTTP 503 indicates unavailable terrain data.

`last_reachable` for failed automatic ice goals is a known remaining limitation; do not describe it as the best alternative destination.

Scenario climate is model output; historical temperatures are partial and acquired at different times. Radiation is a uniform off-region Gale reference. Terrain candidates are neither verified shelters nor confirmed caves.

## Start and connect

From the backend repository:

```powershell
.\.venv\Scripts\python.exe -m uvicorn olympustrail.api:app --host 127.0.0.1 --port 8000
```

`GET /sites` resolves “best base”: take `sites[0].position` and pass only its row/col OR lon/lat pair. There is no `start: {"site": 1}` shortcut.

`localhost` points to your own computer. If you use another teammate's backend, agree a reachable address; shared hosting and browser CORS setup remain pending. The `/ask` shape in your screenshot belongs to your service: adapt this backend result to that shape and preserve its status and warnings.
